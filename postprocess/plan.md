# Data Cleanup & VA Enhancement Plan

This plan tracks the new initiative to clean historical predictions under `postpreprocess/data`, retrain valence/arousal regressors from `subtask3/data`, and re-score the historical outputs per domain. Tasks are grouped into three phases corresponding to your idea and include expected inputs/outputs plus pointers to relevant directories.

## Project Structure References
- `postpreprocess/data/` – legacy prediction JSONL files (laptop/restaurant) with noisy `Quadruplet` entries.
- `postpreprocess/clean/` – cleaned JSONLs generated by Phase 1 scripts.
- `postpreprocess/enriched/` – outputs after re-scoring VA in Phase 3.
- `subtask3/data/` – labeled training/dev JSONLs provided by the competition.
- `postpreprocess/va_regression/` – vendored VA regression utilities (derived from `src/`).
- `postpreprocess/scripts/` – CLI entry points that orchestrate cleaning/training/inference.

## Phase 1 – Historical JSON Cleanup
- [x] **Inventory sources**  
  - *Input*: `postpreprocess/data/*.jsonl`  
  - *Output*: catalog listing domain, timestamp, run metadata (store in `postpreprocess/README.md`).
- [x] **Text normalization & `[UNK]` removal**  
  - Strip `[UNK]`, trim whitespace, and collapse multiple spaces in `Text`, `Aspect`, `Opinion`.  
  - *Output*: cleaned JSONL per file under `postpreprocess/clean/{domain}_{run}.jsonl`.
- [x] **Empty quadruplet filtering**  
  - Drop records with empty `Quadruplet` arrays or fill with placeholder notes; log counts.  
  - *Output*: summary CSV (`postpreprocess/clean/cleanup_stats.csv`) tracking removals per file.
- [x] **Schema validation**  
  - Reuse `scripts/sample_and_validate.sh` or add a stricter checker ensuring `Aspect/Opinion/Category/VA` presence.  
  - *Output*: validation report (pass/fail) per cleaned file.

## Phase 2 – Domain-Specific VA Regression Training
- [x] **Feature preparation**  
  - *Input*: `subtask3/data/zho_{domain}_train_alltasks.jsonl`.  
  - *Output*: domain-specific feature matrices + target arrays stored in `va_models/features/{domain}_train.pkl`. Include indicators for whether RAG neighbor stats are used.
- [x] **Model selection & training**  
  - Start with Gradient Boosting; compare against lightweight neural or k-NN smoothing if needed.  
  - *Output*: trained models in `va_models/{domain}_va.pkl` plus training metrics (`va_models/{domain}_metrics.json`).
- [x] **Cross-validation / dev evaluation**  
  - Hold out a portion of the labeled training data (dev JSON lacks gold VA) to estimate RMSE/Pearson.  
  - *Output*: evaluation summary appended to `src/experiments/results.md` (or new table if preferred); metrics also logged in `postpreprocess/models/*_metrics.json`.
- [x] **Documentation update**  
  - Amend `README.md` to describe the new cleaning + VA procedure and expected CLI usage.

## Phase 3 – Re-scoring Historical Predictions
- [x] **Batch inference pipeline**  
  - *Input*: cleaned files from Phase 1 + trained VA models from Phase 2.  
  - *Output*: enriched JSONLs written to `postpreprocess/enriched/{domain}_{run}.jsonl` with updated `VA`.
- [ ] **Consistency checks**  
  - Ensure every quadruplet receives a non-empty `VA`; flag files with missing predictions.  
  - *Output*: QA log summarizing any failures.
- [ ] **Comparative analysis**  
  - Plot or tabulate VA distribution before vs. after enrichment for each domain/run.  
  - *Output*: `postpreprocess/reports/{domain}_{run}_va_comparison.md` with brief interpretation.
- [ ] **Integration decision**  
  - Decide whether enriched outputs replace originals or remain side-by-side; update downstream scripts accordingly.  
  - *Output*: final note in this plan and `README`.

Keep the checkboxes updated as tasks complete so progress is visible. Adjust phases as requirements evolve.
